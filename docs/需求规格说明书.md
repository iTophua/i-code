# i-code 轻量级编辑器 · 需求规格说明书

> 版本：v1.1 · 日期：2026-08-02
> 定位：个人日常使用的轻量级代码编辑器（含代码智能）

---

## 一、项目概述

### 1.1 一句话定位

一个**轻量、跨平台**的桌面编辑器，面向"AI 辅助编码后的审核 + Git 全流程 + 项目内终端 + 代码轻编辑 + 便签记录"的日常场景。

### 1.2 核心设计原则

| 原则 | 含义 |
|---|---|
| **轻量优先** | 安装包小、内存可控、启动快；LSP 采用"探测系统已装 server"策略，零打包体积成本 |
| **够用就好** | 不追求替代 VS Code，只做好 5 个核心场景 + 代码智能 |
| **跨平台** | macOS / Windows / Linux 一等支持 |
| **数据自持** | 便签等持久数据独立于项目文件，存入应用数据目录 |

### 1.3 明确不做的事（范围边界）

为守住"轻量"定位，以下功能**明确排除**：

- ❌ 终端分屏
- ❌ 终端 SSH 远程连接
- ❌ 便签的分类、标签体系、合并导出
- ❌ 行内批注 / 评论系统
- ❌ 插件 / 扩展市场
- ❌ Language Server 打包分发（改为探测系统已装，见 3.11）

## 二、用户场景

### 场景 ① AI 编码后审核

AI 完成代码生成后，打开项目查看改动。

- 查看 Git 改动（侧栏 diff 视图），快速定位修改了哪些文件
- 点击改动文件，对照查看修改前/后内容
- 阅读代码和文档，评估质量
- 发现小问题时，直接手动编辑修正
- 偶尔需要追代码上下文，用全局搜索查找引用

**关键体验**：改动一目了然，从 diff 到代码无缝切换，随时能动手改。

### 场景 ② Git 全流程操作

日常 Git 操作的完整覆盖。

- 基础：status / diff / commit / pull / push / log
- 分支：checkout / merge / 创建 / 删除 / 分支图
- 进阶：rebase / stash / cherry-pick / **冲突解决（三向合并）**
- 溯源：blame / 文件历史 / 某行的变更追溯

**关键体验**：不用切到命令行就能完成绝大多数 Git 操作；冲突时有可视化的三向合并工具。

### 场景 ③ 项目内终端

在当前项目下直接使用终端。

- 多标签终端，可同时运行多个命令
- 新建终端默认 `cwd = 当前项目根目录`
- 标准终端体验（颜色、历史、补全、快捷键）

**关键体验**：打开项目即有终端，跟随项目目录。

### 场景 ④ 代码查看与轻编辑

浏览和简单修改代码。

- 全语言语法高亮
- 打开任意文件（按扩展名识别语言）
- 基础编辑：多光标、查找替换、撤销重做
- 大项目支持（上万文件、文件树虚拟滚动）
- **大文件/日志查看**（几百 MB，查找 + 查看，只读）
- 工具：JSON/SQL 格式化压缩、XML/HTML/CSS/JS 美化

**关键体验**：打开什么都流畅，大项目不卡，大日志能看能搜。

### 场景 ⑤ 便签记录

随手记录文字，部分内容不落项目文件但需持久保留。

- 便签列表（量小，几十条），搜索 + 置顶管理
- 全局便签（不属于任何项目）和项目级便签（跟随特定项目）
- 便签内容支持语法高亮（可指定语言，如 SQL/JSON）
- 跨应用重启保留，自动保存

**关键体验**：随手记、随手找、重启不丢。

### 3.3 大文件 / 日志查看器（Log Viewer）⭐ 重点子系统

> **背景**：用户有几百 MB 的日志文件，需要做查找和查看。Monaco 完全无法承载（JS 字符串内存翻倍 + DOM 渲染会崩溃）。这是一个独立的、基于流式分块 + 虚拟滚动的只读查看器。

#### 功能规格

| 需求 | 规格 |
|---|---|
| 容量目标 | 支持打开 **数百 MB** 级别文件 |
| 模式 | **只读**（不编辑大文件，无实际意义且不可行） |
| 渲染 | 虚拟滚动，只渲染可视区域行 |
| 导航 | 跳转到行号、滚动条拖拽（基于行索引秒跳） |
| 搜索 | 全文搜索，返回所有匹配行，支持上/下一个跳转 |
| 编码 | 仅 UTF-8（日志文件通常为 UTF-8） |
| 内存 | 不将整个文件载入内存，按需分块读取 |

#### 技术方案（前端 + Rust 协作）

```
                     前端 (虚拟滚动 UI)
                         │
            ┌────────────┼────────────┐
            ▼            ▼            ▼
       行索引查询    分块读取      全文搜索
            │            │            │
            ▼            ▼            ▼
  ┌─────────────────────────────────────────┐
  │           Rust 后端（按需读取）            │
  │                                          │
  │  1. 行偏移索引 (Line Offset Table)        │
  │     打开文件时流式扫描一次，记录每行        │
  │     的字节偏移，缓存到内存 / 索引文件       │
  │                                          │
  │  2. 分块读取 (Chunked Read)               │
  │     给定 [start_line, end_line]，         │
  │     用索引定位字节偏移，读取该区间返回       │
  │                                          │
  │  3. 流式搜索 (Streaming Search)           │
  │     按块扫描文件，返回匹配行号+内容+        │
  │     上下文行，前端高亮展示                   │
  └─────────────────────────────────────────┘
```

**关键设计点**：

1. **行偏移索引**
   - 打开大文件时，Rust 侧流式扫描一次，记录每行起始字节偏移。
   - 索引驻留内存（几百 MB 文件约几百万行，偏移数组约几十 MB，可接受）。
   - 二次打开同一文件且未修改时，复用缓存的索引（可落盘 `.idx` 旁路文件）。

2. **分块读取**
   - 前端虚拟滚动触发：可见区域约 50–100 行 → 向 Rust 请求该区间。
   - Rust 用索引定位字节偏移，`seek + read` 只读需要的部分。
   - 预读缓冲：当前可视区上下各预读一屏，减少往返。

3. **全文搜索**
   - Rust 侧按固定块（如 4MB）流式扫描，内存占用恒定。
   - 返回结构：`{ line, column, lineContent, contextBefore[], contextAfter[] }`。
   - 结果分页返回（匹配太多时），前端用列表展示 + 上/下一个跳转。

4. **内存模型**
   - 前端：只持有当前视窗 + 预读缓冲的文本（约几十 KB），**永不持有全文**。
   - 后端：行索引在内存，文件内容按需读取，**永不全文载入**。

#### 3.4.1 三向合并编辑器（3-Way Merge）

| 需求 | 规格 |
|---|---|
| 触发 | 检测到冲突文件（`<<<<<<<` 标记）时，提供"解决冲突"入口 |

### 3.11 代码智能（LSP / Language Server Protocol）

> **定位转变**：从"纯高亮编辑器"升级为"具备代码智能的轻量编辑器"。LSP 能力让 AI 编码审核、代码阅读体验产生质变（跳转定义、引用查找、错误诊断），是审核 AI 生成代码时最关键的生产力工具。
>
> **轻量策略**：不打包任何 Language Server，应用启动时探测系统 PATH 中已安装的 server，有则启用、无则降级为纯高亮——零打包体积成本，只对已装工具链的用户生效，完全契合"轻量"定位。

#### 3.11.1 能力清单（全套 LSP 能力）

| 能力 | 说明 | 优先级 |
|---|---|---|
| 跳转定义 | `F12` / `Ctrl/Cmd+Click` 跳转到符号定义（跨文件） | P0 |
| 引用查找 | `Shift+F12` 查找符号的所有引用，结果面板展示 | P0 |
| 悬停提示 | hover 显示符号的类型/文档 | P0 |
| 错误诊断 | 编辑时实时显示错误/警告（波浪线 + Problems 面板） | P0 |
| 自动补全 | 输入时弹出补全建议（智能、基于上下文） | P0 |
| 符号重命名 | `F2` 安全重命名符号（跨文件） | P1 |
| 文档符号 | 当前文件的符号大纲（Outline 面板），配合面包屑 | P1 |
| 格式化 | 整理代码格式（**复用 LSP formatting provider，替代独立 formatter 库**） | P1 |
| 代码动作 | 快速修复 / 重构建议（lightbulb） | P2 |
| 查找实现 | 跳转到接口/抽象的实现 | P2 |

#### 3.11.2 语言支持范围

**A. Monaco 内置语言能力（零额外成本，开关即可）**

| 语言 | 能力 | 说明 |
|---|---|---|
| TypeScript / JavaScript / JSX / TSX | 补全、诊断、跳转、hover、格式化 | Monaco 内置 tsserver（worker 内运行） |
| JSON | 校验、补全（含 schema） | Monaco 内置 |
| CSS / SCSS / Less | 补全、校验 | Monaco 内置 |
| HTML | 补全、校验 | Monaco 内置 |
| SQL | 高亮、基础补全 | Monaco 内置 |

**B. 外部 Language Server（探测系统已装）**

| 语言 | Server | 探测命令 | 说明 |
|---|---|---|---|
| **Go** | `gopls` | `gopls version` | **首批支持** |
| **Python** | `pyright` / `pylsp` | `pyright --version` / `pylsp --version` | |
| **Rust** | `rust-analyzer` | `rust-analyzer --version` | |
| **Java** | `jdtls` (Eclipse JDT.LS) | 检测 `jdt-language-server` | |
| **C/C++** | `clangd` | `clangd --version` | 可选 |

> 探测逻辑：应用启动时（或打开项目时）扫描系统 PATH，逐个检测 server 是否存在。存在则在该语言生效 LSP 全套能力；不存在则**静默降级**为纯高亮，并在设置页提示用户"检测到未安装 gopls，可执行 `go install gopls@latest` 启用 Go 代码智能"。

#### 3.11.3 技术架构

```
┌─────────────────────────────────────────────────────┐
│  Monaco Editor (WebView)                            │
│   ├─ TS/JS: 内置 web worker (tsserver)              │
│   └─ 外部语言: monaco-languageclient 桥接           │
└───────────────────┬─────────────────────────────────┘
                    │  LSP over JSON-RPC
┌───────────────────┴─────────────────────────────────┐
│  Language Client (前端，monaco-languageclient)       │
│   • 每种外部语言一个 LanguageClient 实例             │
│   • 把 Monaco 的动作（跳转/补全/hover）转成 LSP 请求 │
└───────────────────┬─────────────────────────────────┘
                    │  JSON-RPC (stdin/stdout)
┌───────────────────┴─────────────────────────────────┐
│  Rust 后端: Server 进程管理                          │
│   • 探测系统 PATH 中的 server                        │
│   • 启动/重启/销毁 server 子进程                     │
│   • 转发 LSP 消息（前端 ↔ server）                   │
│   • 多 workspace 能力                                │
└───────────────────┬─────────────────────────────────┘
                    │  spawn
┌───────────────────┴─────────────────────────────────┐
│  Language Server 子进程（系统已装）                  │
│   gopls / pyright / rust-analyzer / jdtls / clangd  │
│   每个常驻内存 50–200MB（按语言）                     │
└─────────────────────────────────────────────────────┘
```

**关键库**：
- 前端：`monaco-languageclient`（Monaco ↔ LSP 桥接）、`vscode-languageclient` 协议实现
- 后端：Rust 负责子进程生命周期 + JSON-RPC 消息转发

#### 3.11.4 生命周期与资源管理

| 场景 | 行为 |
|---|---|
| 启动 | 探测已装 server；**不立即启动**，等到首次打开该语言文件时才 spawn（懒启动） |
| 工作区切换 | server 跟随工作区根（workspaceFolders），切换时通知 |
| 关闭项目 | 销毁该项目的 server 实例，释放内存 |
| server 崩溃 | 自动重启（最多 3 次），失败则降级纯高亮并提示 |
| 应用退出 | 杀掉所有 server 子进程 |

#### 3.11.5 内存预算（LSP 开启时）

| 组件 | 内存 | 说明 |
|---|---|---|
| 基础（WebView + Monaco + UI） | 200–300MB | 不变 |
| 每个活跃外部 server | 50–200MB | 取决于语言和项目大小 |
| **典型场景**（TS + 1 个后端 LSP） | **300–500MB** | 可接受，仍优于 Electron 同等配置 |

> 可在设置中**全局关闭 LSP** 或**按语言关闭**，回到纯高亮模式以省内存。

#### 3.11.6 设置项

```jsonc
{
  "languageServer": {
    "autoDetect": true,          // 启动时探测系统 server
    "languages": {
      "go": { "enabled": true, "path": "gopls" },
      "python": { "enabled": true, "path": "pyright" },
      "rust": { "enabled": true, "path": "rust-analyzer" }
    },
    "diagnostics": true,         // 错误诊断
    "completion": true,          // 补全
    "formatOnSave": false        // 保存时格式化
  }
}
```

#### 3.11.7 范围边界（LSP 不做的事）

- ❌ 不打包/下载任何 Language Server（纯探测）
- ❌ 不做 Debug（调试运行）
- ❌ 不做 Test Runner
- ❌ 不做Lint 规则自定义界面（用 server 默认配置）
- ❌ 不做多根 server 复杂共享（每项目独立实例优先简单）

## 五、非功能需求

| 维度 | 指标 | 说明 |
|---|---|---|
| 安装包体积 | 目标 < 20 MB（mac dmg / win msi / linux AppImage） | Tauri + 系统 WebView，不含运行时下载 |
| 冷启动 | < 2 秒（打开空窗口） | Monaco 按需加载，不阻塞首屏 |
| 内存占用 | 空载 200–300 MB（macOS 基准） | WebView + Monaco 的固有成本；Linux/WebkitGTK 略高 |
| 大项目 | 文件树上万项不卡顿 | 虚拟滚动 + 懒加载子目录 |
| 大文件 | 数百 MB 日志可打开、可搜索、内存不爆 | Log Viewer 流式分块，不全文载入 |
| 跨平台 | macOS / Windows / Linux 功能一致 | |
| 数据持久 | 便签、Tab 状态、设置跨重启保留 | SQLite |

> **关于内存**：WebView 架构（系统浏览器内核 + React + Monaco）有固有底线（WKWebView ~70MB + Monaco ~40MB），空载无法做到传统原生编辑器的几十 MB。200–300MB 是该架构的合理区间，仍显著优于 Electron（通常 300–500MB）。详细优化策略见 5.1。

### 5.1 内存与性能优化策略

> 守住 200–300MB 区间需要主动优化，否则打开多 Tab + 终端后会快速膨胀。

| 场景 | 策略 | 落地点 |
|---|---|---|
| **Monaco 语言包** | 按需懒加载语言定义（打开某语言首个文件时才加载），不一次性注册全部 | Monaco loader 配置 |
| **后台 Tab 冻结** | 非活跃 Tab 的 Monaco 模型 detach 但保留状态（文本/光标/Undo 栈），切回时重建；避免 N 个编辑器实例同时驻留 | Tab 管理器 |
| **大文件不进 Monaco** | >20MB 走 Log Viewer（流式），永不进入 Monaco 模型 | 文件分档（3.3） |
| **终端 scrollback 限制** | 默认 5000–10000 行滚动缓冲，超出丢弃旧行 | xterm.js 配置 |
| **文件树虚拟滚动** | 只渲染可视节点，懒加载子目录 | 文件树（3.1.9） |
| **Diff 完成即销毁** | diff/合并视图关闭后立即释放对应 Monaco 模型 | Git 面板 |
| **便签按需渲染** | 便签编辑器实例只给当前选中的便签，切换即销毁重建 | Scratchpad |
| **图片/资源** | 禁用 WebView 的图片缓存侵略性策略，媒体资源按需 | 全局 |
| **GC 友好** | 关闭 Tab/终端/便签时显式 dispose（Monaco model、xterm、worker） | 生命周期管理 |

### 5.2 启动性能策略

| 阶段 | 策略 |
|---|---|
| 首屏 | 先渲染应用壳 + 欢迎页/文件树，Monaco 延迟加载（动态 import） |
| 会话恢复 | 并发恢复 Tab 列表（只恢复路径/光标），不立即渲染全部 Monaco 实例；活跃 Tab 才挂载 |
| 按需加载 | 命令面板、设置页、Git 面板等非首屏模块用 React.lazy + Suspense 分包 |

| **M4 LSP 代码智能** | Monaco 内置语言能力开关、**LSP 基础设施**（探测/进程管理/monaco-languageclient 桥接）、**Go(gopls) 首批**、跳转/引用/hover/诊断/补全、Problems 面板、Outline | ① ④ |
| **M5 大文件查看器 + 工具集 + 打磨** | 日志查看器（行索引/分块/流式搜索）、JSON/SQL 格式化（**复用 LSP formatting**）、小工具、只读审核模式、**编辑器分栏**、**符号面包屑**、**Zen 模式**、**工作区多项目组**、**其他后端 LSP（pyright/rust-analyzer/jdtls）**、主题、打包 | ① ④ |

> 说明：
> - 会话恢复/最近项目/编辑手感配置提前到 M1——它们是"每天打开就能用"的基础体验。
> - **LSP 独立成 M4**：它是质变功能且工程量较大（monaco-languageclient 桥接 + 进程管理），独立一期专注做好；Go 首批落地，验证架构后再扩语言。
> - 格式化能力放 M5：因为 LSP formatting provider 是更优方案（M4 LSP 落地后即可复用），比独立引入 prettier/sql-formatter 更省事且更准。
> - 分栏/Zen/符号面包屑/工作区等增强能力放 M5 打磨期。
